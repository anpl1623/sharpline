# ADR 0007: Move the frontend from Next.js 15 to Next.js 16

- **Status:** Accepted
- **Date:** 2026-08-19
- **Charter reference:** CLAUDE.md §7, §14
- **Supersedes:** the "Next.js 15" pin in CLAUDE.md §7 and in ADR 0001's frontend note

## Context

CLAUDE.md §7 fixed the frontend at "TypeScript + Next.js 15 (App Router)" and marked it
"not negotiable". That pin held through phases 0–5.

The CI Trivy gate then failed the `web` image on 9 findings (8 HIGH, 1 CRITICAL). Most of
them turned out not to be this application's dependencies at all — they were npm's own
vendored tree inside `node:24-alpine`, and they were removed by deleting the package
manager from the runtime stage (see the commit that introduced that change).

Two findings were genuinely ours, reachable only through `next`:

- **postcss** — four advisories, the most serious being arbitrary `.map` file disclosure via
  an attacker-controlled `sourceMappingURL`
- **sharp** — inherited libvips CVEs (CVE-2026-33327, -33328, -35590, -35591)

`npm audit` offered exactly one remedy for both: `next@16.3.1`.

## Decision

**Move to Next.js 16.** CLAUDE.md §7 and §14, README's parity table, and the frontend note
in ADR 0001 are updated accordingly.

The interim fix — npm `overrides` pinning patched `postcss` and `sharp` beneath an
unchanged Next 15 — was implemented, verified, and then **reverted** in favour of the
upgrade. It worked, but it is the kind of fix that quietly accumulates: each override is a
standing claim that a transitive dependency can be swapped under a framework that was not
tested against it, and nothing re-checks that claim.

That risk was not hypothetical here. A second batch of overrides added at the same time as
a "defensive floor" — `tar`, `undici`, `ip-address`, `brace-expansion` — broke the lint
toolchain outright: `brace-expansion@5` changed its export shape, and the bundled
`minimatch` that expects the older API failed with `TypeError: expand is not a function`.
Those four were pinning packages that (a) had already been removed from the runtime image
along with npm and (b) are devDependencies that never reach `.next/standalone`. They bought
nothing and cost a working `eslint`. All overrides are now gone.

## Consequences

**Timing is the main reason this is cheap.** `web/src` is still three placeholder files —
`layout.tsx`, `page.tsx`, `globals.css` — because CLAUDE.md §7 requires `/design-consultation`
to run before any component is written, and phase 7 has not started. A major framework bump
costs almost nothing today and would cost considerably more once the odds board, bet slip
and WebSocket client exist.

**What actually had to change:**

- `next` and `eslint-config-next` to `^16.3.1`
- `web/tsconfig.json` — Next 16 mandates `jsx: react-jsx` (the React automatic runtime) and
  rewrote the file to set it
- `web/eslint.config.mjs` — rewritten. `eslint-config-next@16` ships **native flat config**,
  so the `@eslint/eslintrc` `FlatCompat` shim used for v15 is not merely unnecessary, it
  fails: feeding an already-flat config back through the eslintrc compatibility layer throws
  `TypeError: Converting circular structure to JSON` when the validator tries to serialise
  the shared React plugin object. The subpath exports are now imported directly.

**Verified:** `npm audit` reports 0 vulnerabilities; Trivy scans the image clean at
HIGH,CRITICAL; `web-build`, `web-lint` and `web-typecheck` all pass; the image is 179MB,
inside the 200MB target CLAUDE.md §7 sets, and serves HTTP 200.

**Accepted cost.** The charter called the Next 15 pin non-negotiable, and this renegotiates
it. The justification is that the pin existed to fix a *framework and router model* —
React via Next, App Router, TypeScript strict — and 16 changes none of those. Had the
upgrade forced a move off the App Router, the answer would have been to keep the overrides
and carry the risk instead.

## Alternatives considered

**Stay on 15 with `overrides`.** Implemented and working before being reverted. Rejected for
the reasons above: it is a standing untested claim per pin, it hides the real remedy behind
a lockfile detail, and the sibling overrides added alongside it had already broken lint.

**Stay on 15 and allow-list the CVEs in the scan policy.** Rejected outright. A scan gate
that is taught to ignore its findings is the vacuous-check failure mode this project has now
hit three separate times — the CGO guard that could never fail, an API serving zero routes
behind green probes, and a TOTP test that never reached the code it named.

**Wait until phase 7.** Rejected. The cost of this bump rises monotonically with the amount
of UI written against the old version, and phase 7 is the phase that writes all of it.
